## AI エージェントの使用手順

### 前提

- 環境構築手順がすべて完了し、AgentCore Runtime が `READY` 状態であること
- 利用したいチャットツール（Slack／Chatwork）で、本製品の連携アプリまたは連携アカウントが利用可能であること

### 質問の送り方

#### Slack

1. TracisAI を利用したい Slack チャンネルを開く
2. メッセージ欄で `@<Slack App の名前>` を入力し、続けて調べたい内容を日本語で入力して送信する
3. しばらく待つと、同じスレッド内に TracisAI から回答メッセージが投稿される

> TracisAI は Slack のメンション（`app_mention`）されたメッセージのみを処理します。メンションを付けずに発言した場合は応答しません。

#### Chatwork

1. TracisAI を利用したい Chatwork ルームを開く
2. メッセージ欄で TracisAI の連携アカウントにメンションし、続けて調べたい内容を日本語で入力して送信する
3. しばらく待つと、TracisAI から受付メッセージと回答メッセージが投稿される

> TracisAI は Chatwork の `mention_to_me` イベントのみを処理します。連携アカウントにメンションせずに発言した場合は応答しません。

### 質問例

TracisAI は CloudWatch Logs および DB（MySQL）の情報を参照して回答します。質問はできるだけ具体的に、調査範囲（時間帯・対象システムなど）を含めて行うと精度が向上します。

| 例                 | 質問内容                                                                        |
| :----------------- | :------------------------------------------------------------------------------ |
| ログ調査           | `@TracisAI 昨日 10:00〜12:00 の間で order-service にエラーログは出ていますか？` |
| 識別子追跡         | `@TracisAI request_id=abc-123 のリクエストがどこで失敗したか調べてください`     |
| ユーザー単位の追跡 | `@TracisAI user_id=42 が直近1時間で行った操作と、その結果を教えてください`      |
| 異常検知           | `@TracisAI 直近30分で 500 系エラーが急増しているサービスはありますか？`         |

> 上記の `@TracisAI` は Slack での入力例です。Chatwork を利用する場合は、TracisAI の連携アカウントにメンションしてから質問を入力してください。

### 回答までの目安

- 通常、1 つの質問に対する回答までの所要時間は **数十秒〜数分** 程度です
- 調査範囲が広い場合や試行回数が増えると、上記より時間がかかることがあります
- 処理がタイムアウトした場合、回答が届かないことがあります。範囲を絞って再度質問してください

### 使用時の注意事項

- **回答は実データに基づきます**：TracisAI は CloudWatch Logs と DB の実データを参照して回答します。ログに残っていない情報や、ナレッジベースに登録されていない知識については回答できません。
- **ナレッジベースの内容に依存します**：質問対象のロググループやテーブル構造などのメタ情報は [ナレッジベース](/docs/create_environment/05_prepare_knowledgebases/README.md) に登録されている内容を参照します。期待した回答が得られない場合、ナレッジベースの内容を見直してください。
- **DB は識別子経由でのみ参照されます**：オーケストレーターはまず CloudWatch Logs を調査し、ログから識別子（`request_id`、`user_id`、`order_id` など）を抽出できた場合のみ DB を検索します。識別子の手がかりを含む質問にすると、より深い調査につながります。
- **クエリ試行回数には上限があります**：同一質問に対するクエリ試行は最大 3 回までです。3 回試行しても有効な結果が得られない場合、その旨を報告して調査を終了します。
- **個人情報・機微情報の扱いに注意してください**：ログや DB の内容がそのままチャットツールに投稿されるため、機微情報を含む可能性があるロググループ／テーブルをナレッジベースに登録する際は事前にご確認ください。
- **利用に応じてコストが発生します**：質問ごとに Bedrock（生成 AI）と AgentCore Runtime の利用料金が発生します。さらに API Gateway、Lambda、SQS、Knowledge Bases、データ転送量、CloudWatch Logs の料金が発生する場合があります。詳細は [参考コスト](/docs/COSTS.md) を参照してください。
- **詳細な参考コストについて**：想定される AWS 利用料金および AI 利用料金の参考値については [参考コスト](/docs/COSTS.md) を参照してください。

### FAQ / トラブルシュート

#### Q. チャットツールでメンションしても応答しません / 応答は返ってきても最終的な回答がありません

A. 次の点を順に確認してください。

- Slack を利用する場合、利用したい Slack チャンネルに本製品の Slack 連携アプリが招待されていないと、メンションしても処理されません。[Slack App のチャンネル招待手順](/docs/create_environment/03_1_create_slack_app/README.md#slack-app-のチャンネル招待手順) を参照し、Slack 連携アプリを招待してください。
- Chatwork を利用する場合、TracisAI の連携アカウントをメンションしていないと処理されません。[Chatwork Webhook の設定](/docs/create_environment/03_2_create_chatwork_webhook/README.md) を確認してください。
- AgentCore Runtime が `READY` 以外の状態の場合、メンションを送っても回答できないことがあります。AWS コンソールの「Amazon Bedrock AgentCore」で Runtime の状態とログを確認してください。
- チャットツール認証情報用共有 Secret または DB 用シークレット情報の値が未設定、または誤っている場合、エージェントが正常応答できないことがあります。[Secret の準備](/docs/create_environment/04_prepare_secret/README.md) を参照して設定内容を確認してください。

上記に当てはまらない場合、一時的な AWS 障害などにより AI エージェントにメッセージが到達していない可能性があります。

- AWS 側の障害有無を確認してください。
- 受け付けたメッセージは最大 30 分間保持されますが、障害や滞留が長引いた場合、メッセージが自動的に削除され、再度質問が必要になる可能性があります。
- 一時的な障害から復旧した後に、対象の質問をあらためて再実行してください。
- 障害中はリクエストがすぐに完了しない、または再試行される可能性があります。

#### Q. 回答が返ってくるまで時間がかかります

A. 次のような要因が考えられます。

- 調査範囲が広い場合や試行回数が増える場合、回答までに数十秒から数分かかることがあります。
- 質問は順番に 1 つずつ処理されるため、連続して質問を送ると、待ち時間が長くなることがあります。
- 受け付けたメッセージは最大 30 分間保持されます。保持期間を超えた古いメッセージは削除されるため、処理が長く止まった場合などには処理対象から外れる可能性があります。

#### Q. AgentCore Runtime が `READY` になりません

A. Runtime の作成または更新に失敗している可能性があります。次を確認してください。

- Runtime の状態が `CREATE_FAILED` または `UPDATE_FAILED` の場合は、CodeBuild のログと AgentCore Runtime のログを確認し、設定を修正して `[prefix]-tracis-deploy-agent` を再実行してください。

#### Q. シークレット情報が間違っている、または保存先が存在しません

A. シークレット情報の設定不備があると、問い合わせ完了前に処理が失敗し、正常応答できない可能性があります。

- 保存先のシークレット名が正しいか確認してください。自動作成されたシークレット名は、CodeBuild の `terraform apply` 完了時の Outputs から確認できます。
- DB 用シークレット情報は `username` と `password`、チャットツール認証情報用共有 Secret は `SLACK_SIGNING_SECRET`、`SLACK_BOT_TOKEN`、`CHATWORK_WEBHOOK_TOKEN`、`CHATWORK_API_TOKEN` が正しいキー名で登録されているか確認してください。
- 値を更新した場合、Secret のキャッシュが失効するまで最大 5 分程度かかることがあります。

#### Q. ナレッジベースを更新したのに回答へ反映されません

A. ナレッジベースの同期が完了していない可能性があります。

- [ナレッジベースの準備](/docs/create_environment/05_prepare_knowledgebases/README.md) を参照し、同期用 S3 バケットへ更新したデータをアップロードしてください。
- ナレッジベースの同期を実行し、ステータスが `利用可能` になることを確認してください。

#### Q. リソースを削除してよいか分かりません

A. 停止や削除を行う前に、利用影響を確認してください。

- 現在の手順では、ユーザー操作による停止や削除を防ぐ削除保護は提供していません。不要と判断できる場合のみ操作してください。
- 誤って一部のリソースを削除してエージェントが正常に動かなくなった場合は、[利用終了時の環境削除手順](/docs/delete_environment/README.md) および [利用開始時の環境構築手順](/docs/create_environment/README.md) を参照のうえ、関連リソースの削除と再作成を行ってください。その際は、ナレッジベースの登録内容や Secret の値も削除されるため、再作成時に復元できるようあらかじめ退避を行うなどして削除を実行してください。

#### Q. 広い範囲での調査や一度に複数の調査をリクエストすると失敗することがあります

A. Bedrock モデルの最大トークン数上限に達している可能性があります。

- CloudFormation スタックの `BedrockModelMaxTokens` パラメータで、モデルが一度に扱えるトークン数の上限を設定しています。
- この上限を超えるトークンを処理しようとした場合、エージェントの処理が失敗する可能性があります。
- まずは入力内容を見直し、検索対象の範囲（時間帯やシステムなど）を絞る、依頼内容を 1 つの調査に絞るなど、1 回の質問で扱う範囲を狭めることを推奨します。
- 必要に応じてスタックのパラメータを更新して上限を見直してください。ただし、トークン上限を増やすほど Bedrock のトークン使用コストも増加します。
