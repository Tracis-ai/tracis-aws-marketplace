# ナレッジベースの準備


## 作業内容

1. Setup アプリ、または手動アップロードでエージェントに参照させたい情報を準備する
2. 準備した情報をナレッジベースに同期し、結果を確認する


## 前提条件

- [エージェント関連リソースの初期構築](/docs/create_environment/02_build_agent/README.md) までの手順が完了し、 [`knowledge_base_data_source_bucket_name`](/docs/create_environment/02_build_agent/README.md#控えておくべき出力値) の S3 バケットが作成されていること

## 準備方法の選択

- Setup アプリを有効にしている場合は、次の「Setup アプリによる準備」に従って、Slack から対象を選び、コンテキストを編集して登録できます。現在の Setup アプリの認証・リンク発行は Slack のみ対応しています。
- Setup アプリを使用しない場合は、後半の「手動でのデータのアップロード手順」と「ナレッジベースの同期手順」に従ってください。Chatwork のみを利用する場合も手動で準備します。

## Setup アプリによる準備

### 初期設定の確認

- CloudFormation の `EnableSetupApp=true` を指定し、`[prefix]-tracis-deploy-agent` が成功していること
- [Slack App の作成](/docs/create_environment/03_1_create_slack_app/README.md) の Setup アプリ用 Redirect URL 設定と、 [Secret の準備](/docs/create_environment/04_prepare_secret/README.md) の `SLACK_CLIENT_ID` / `SLACK_CLIENT_SECRET` を含む格納が完了していること
- MySQL テーブルを扱う場合は、MySQL の接続設定と DB Secret の準備が完了していること
- [Slack App のチャンネル招待手順](/docs/create_environment/03_1_create_slack_app/README.md#slack-app-のチャンネル招待手順) の利用範囲・運用方法を確認し、App の招待先と参加メンバーを適切に管理していること

### Slack から認証する

1. Slack App を招待済みの Slack チャンネルで、次のメッセージを送信する

   ```text
   @<Slack App の名前> setup
   ```

   `setup` の代わりに `セットアップ` も使用できます。他の説明文は付けずに送信してください。

2. 返信の [セットアップ画面を開く] を選択する（返信は自分だけに表示されます）
3. [Slack で認証] を選択し、リンクを要求した本人の Slack アカウント・ワークスペースで認証する
4. Setup アプリに「認証が完了しました。」とセッション期限が表示されることを確認する

リンクは本人用です。別の利用者へ転送せず、やり直す場合は Slack から新しいリンクを取得してください。

### ロググループ・DB テーブルを選ぶ

1. `参照対象を選択` で [リソースの種別] を選ぶ（`すべて`、`CloudWatch Logs`、`MySQL`）
2. CloudWatch Logs は `ロググループの前方一致検索` に名前の先頭部分を入力し、 [ロググループを検索] を選択する。追加ページがある場合は [さらに読み込む] を選択する
3. MySQL は `テーブル名で絞り込む` で対象を絞る。 [スキーマを見る] でカラム定義を確認する
4. 対象のチェックボックスを選ぶ。ロググループと MySQL テーブルは合計 20 件まで選択できる
5. 選択済みリソースを確認し、 [選択内容を確認] を選択する

MySQL は設定済みの DB のテーブルを表示します。必要なテーブルが見つからない場合は、接続先の DB とテーブル名を確認してください。

### コンテキストを編集・保存する

1. [下書きを生成] を選択する。選択したロググループのメタデータや MySQL のスキーマから Markdown の下書きが作成される
2. `コンテキスト本文` を編集し、業務上の意味、正常・異常の判断基準、テーブルやログの関連を追記する。記載例は後半の「ナレッジベースにアップロードが必要な情報」を参照する
3. プレビューで内容を確認し、 [下書きを保存] を選択する
4. 「保存済み」と表示されたことを確認する

選択を変える場合は [選択へ戻る] を使用します。 [下書きを再生成] や [保存済みの下書きを再取得] では未保存の編集が破棄されるため、確認ダイアログの内容を確認してください。保存はナレッジベースへの登録とは別の操作です。

### AI で説明を補完する（任意）

1. AI に参照させたい本文を [下書きを保存] で保存する（未保存の編集は生成の入力に含まれません）
2. 業務上の用途や判断基準を補う場合は [仕様情報を追加（任意）] を開き、`補足仕様` に入力するか、`補足仕様ファイル` から UTF-8 の `.txt` / `.md` / `.csv` を読み込む（補足仕様の入力は任意です。認証情報は含めないでください）
3. [AIで説明を追加] を選択する。生成結果が表示されるまで待つ
4. `生成候補のプレビュー` で内容を確認する
5. 使用する場合は [編集本文に反映] を選択する。未保存の編集がある場合は、置き換え確認の内容を確認する。使用しない場合は [候補を破棄] を選択する
6. 反映した本文を確認・修正し、 [下書きを保存] を選択する。「保存済み」を確認してから、次のナレッジベース登録へ進む

AI の説明には推測や誤りが含まれる場合があります。業務上の意味や判断基準、テーブルの関連などを確認し、誤った説明があれば修正してください。

### ナレッジベースに登録する

1. `登録状況` で [保存済みの本文を確認し、Knowledge Base への登録に同意します] をチェックする
2. [Knowledge Base に登録] を選択する。未保存の変更がある場合は先に保存する
3. 「同期を開始しています」→「同期中」→「同期が完了しました」となることを確認する。同期は表示される状態を確認しながら待つ
4. 「一部の文書を取り込めませんでした」と表示された場合は、完了表示だけで成功と判断せず、下記の確認を行う

同期には既存文書も含まれます。新しい下書きを登録しても、以前登録した文書は削除されません。

### セッションの有効期限

- セッションには有効期限があります。画面のセッション期限を確認してください
- 期限切れの場合は Slack から再認証してください。前の下書きは再取得できません。

### 主なエラーと確認方法

| 表示・状況                                      | 確認・対処                                                                                       |
| :---------------------------------------------- | :----------------------------------------------------------------------------------------------- |
| リンクが無効・使用済み・期限切れ                | Slack で `setup` を再送し、新しい本人用リンクから開始する                                        |
| Slack の認証を確認できない                      | リンクを要求した本人のアカウント・ワークスペースで認証したか確認する                             |
| 認証が必要・セッション期限切れ                  | 必要な本文を手元へ控え、Slack から再認証する                                                     |
| この操作に必要な権限がない                      | 対象の操作に必要なアクセス権限を確認する                                                         |
| ロググループ・テーブル・スキーマを取得できない  | 画面の再試行を使う                                                                               |
| 下書きを取得・保存できない                      | 本文を手元へ控え、画面のメッセージに従って再試行する                                             |
| 補足仕様ファイルを読み込めない・AI 操作が無効   | UTF-8 の `.txt` / `.md` / `.csv` であることを確認し、画面のメッセージに従って入力を修正する      |
| AI で説明を追加できない・生成がタイムアウトした | 再試行する                                                                                       |
| 保存済みの下書きが更新されている                | 編集中の本文を手元へ控え、保存済みの下書きを再取得する。必要な編集を反映・保存した後、再試行する |
| 同期開始の確認待ち・登録結果を確認できない      | [登録を再確認] を選択する                                                                        |
| 自動確認を終了・同期状態を取得できない          | [状態を再確認] を選択する                                                                        |
| 同期に失敗・停止・一部文書の取り込み失敗        | ナレッジベースのデータソースで同期結果と失敗理由を確認する                                       |

## ナレッジベースにアップロードが必要な情報
- 探索対象となるロググループの情報 ~ ※1
- ログやデータベースに関するメタ情報 ~ ※2

**※1 本製品ではナレッジベースの情報を元に探索対象のロググループを決定・調査する仕様のため、探索対象のロググループ情報をアップロードする必要があります。**
**※2 本製品による調査精度を向上させるためにはロググループやデータベースに関するメタ情報をアップロードしてください。**

### 「ログやデータベースに関するメタ情報」の例

例えば次に記載するような内容を情報として含めていただくことで、本製品による調査精度の向上が見込まれます。

- どのロググループにどのような内容のログが入っているかなどのメタ情報
- ログの正常系・異常系の判断基準
- データベースのどのテーブルにどのような情報が保存されているかなどのメタ情報
- ロググループとデータベースの相関関係

## 手動でのデータのアップロード手順

1. AWS コンソールで「Amazon S3」の画面を開く 
2. 左サイドメニューの [汎用バケット] を選択
3. `バケット` 一覧から [`knowledge_base_data_source_bucket_name`](/docs/create_environment/02_build_agent/README.md#控えておくべき出力値) で確認した名前のバケットを開く
4. `オブジェクト` セクションの [アップロード] をクリック
5. 準備したファイルをアップロード画面に追加して `アップロード` をクリック
6. ファイルがアップロードされていることを確認する


## ナレッジベースの同期手順

1. AWS コンソールで「Amazon Bedrock」の画面を開く 
2. 左サイドメニューの [ナレッジベース] を選択し、対象のナレッジベースをクリック
3. `データソース` セクションの対象のデータソースを選択する
4. [同期] をクリック
5. ステータスが `進行中` から `利用可能` に変わったことを確認する


## ナレッジベース作成後のデータ更新手順
1. 上記の「手動でのデータのアップロード手順」を参考にナレッジベース同期用 S3 バケットの内容を更新する
2. 上記の「ナレッジベースの同期手順」の要領でナレッジベースの同期を行う
